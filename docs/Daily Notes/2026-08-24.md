## Mod Store: universal module system, phase 1 (registry infrastructure)

Long design conversation (interviewed extensively, plan at
`/home/logcore/.claude/plans/i-want-you-to-composed-scone.md`) landed on a much bigger scope than
the original "browsing-only Mod Store catalog" from earlier sessions: every module in the app —
including foundational ones like Tasks, Chat, and Dashboards — will eventually convert into a
uniform `module_packages/<id>/` format, each with its own manifest/version/changelog. A locked
module just carries `uninstallable=True` rather than being excluded from the system. Real
infrastructure (`dashboard_blocks/`, `agent_service.py`'s tool-orchestration engine) is explicitly
excluded — no router of their own, imported by every module, never a module themselves.

Today's actual code is the foundation only: the registry mechanism (`module_registry.py`), the
Mod Store service/router (`mod_store_service.py`/`routers/mod_store.py`), and all four
enforcement-gap fixes (Brain browser, AI agent tools, dashboard blocks, export-as-deliberate-no-op)
wired generically off a module's manifest — built and fully tested with **zero real modules
converted yet** (`module_packages/` is empty except `__init__.py`). Journal's actual conversion
(increment 1 in the plan) is still pending — tracked in `docs/TASKS.md`.

### Real bugs caught by writing tests before trusting the design

1. `discover_manifests()` was blindly importing every directory under `module_packages/`,
   including `__pycache__` once Python compiled bytecode for it. Fixed: require an actual
   `manifest.py` file, skip `_`-prefixed dirs.
2. Route ordering: the SPA catch-all was registered via `@app.get` at plain import time, but module
   routers can only register inside `lifespan()` *after* migrations run (a locked module's
   install-state depends on its own upgrade migration). Starlette matches by insertion order, so
   the catch-all had to move into `lifespan()` too, positioned last — otherwise it would have
   shadowed every module route. Verified via a real `TestClient` lifespan run, not just imports.
3. A locked module's registration failure needed to crash boot loudly, not log-and-skip like an
   optional module — the lenient path would leave the app looking healthy while something as
   load-bearing as Tasks was silently missing.

### Design corrections made mid-build (caught by reasoning through edge cases, not just coding)

- Brain-browser/agent-tool module gating is **per-user** (checked against the caller's
  `disabled_modules`), not instance-wide — a module can be installed for the instance but disabled
  for one role/user, and that case must hide its folder too. First draft only handled "never
  installed at all."
- Dashboard block gating threads the module check through **whichever identity `render_block()` is
  actually resolving as at that pass** (viewer at pass 1, owner at pass 2's
  `share_underlying_data` exception) — not a flat "check the owner" shortcut. Verified with a test
  where the viewer has the module off but the owner has it on (resolves as owner) and one where
  both have it off (stays locked).
- `features_service.ALL_MODULE_IDS` → `all_module_ids()` touched 4 files, not the 2 originally
  assumed — `routers/auth.py` had a second validator (`WorkspaceModulesRequest`) using the same
  name that a first pass missed.

### Real gap found mid-conversion

`write_journal_entry` wasn't in `_RESEARCH_TOOLS`/`_READ_TOOLS` — core's "new tools are write-gated
by default" rule — but the phase-1 module-tool plumbing had no way for a module to declare which of
its own tools are read-only. Without a fix, `read_journal_entry` would have silently stopped
working in research mode and started requiring approval in approve mode, a real regression from
today's behavior. Fixed: `ModuleManifest` gained `read_only_agent_tools`; both `agent_service.py`
call sites now union it in via `module_registry.read_only_agent_tool_names()`.

### Test infrastructure fix (affects every future module conversion, not just journal)

A module's own tests need the same fixtures as `app/backend/tests/`, but conftest.py fixtures only
inherit down a directory tree, not across sibling ones. Moved the shared fixtures to a new
`app/backend/conftest.py` (the true common ancestor of `tests/` and `module_packages/`), deleted
the old `tests/conftest.py`, and added `testpaths = ["tests", "module_packages"]` to
`pyproject.toml` so a bare `pytest`/`pytest -v` covers both trees. `pytest tests/ -v` still narrows
to core-only when that's what's wanted (an explicit path on the command line overrides testpaths).

## Journal conversion, frontend half (increment 1 complete)

Finished journal's conversion end-to-end. `src/lib/moduleRegistry.js` (`import.meta.glob`) auto-
discovers every converted module's frontend manifest at build time — `constants.js`, `deepLinks.js`,
`blockRegistry.js` all merge it in generically now, no per-module edit needed going forward. Moved
`pages/Journal.jsx`, its `JournalEntryBlock` component, and its `lib/api.js` client into
`module_packages/journal/frontend/`. `lib/api.js`'s `get`/`post`/`put`/`patch`/`del` are now
exported so a module's own client can build on the shared session/error-handling logic instead of
reimplementing it.

New `activeModuleIds` in `AuthProvider` (from `GET /mod-store/active`, same poll cadence as the
user), closing a real gap `disabledModules` alone can't: between clicking Install and clicking
Restart Now, the marker says installed but the backend hasn't registered the router yet.
`ModuleRoute` now requires both signals for a converted module's route. Nav itself needed zero
changes — `Layout.jsx`'s existing `disabledIds` filter already worked correctly once `ALL_MODULES`
included the merged-in entries.

### Verified against a real running instance, not just pytest

Started an actual `uvicorn` dev server against a real Brain (copied from the real setup template),
registered a real user through the real `/auth/register` flow, then ran the full cycle over real
HTTP: catalog → install → confirmed `/mod-store/active` still empty and `disabled_modules` already
cleared (marker flips immediately, router doesn't) → restarted the process → confirmed `/mod-store/
active` now includes journal and `GET /api/v1/journal` returns real `application/json` (a genuine
gotcha found here: an unregistered path doesn't 404, it falls through to the SPA catch-all's
`index.html`, which is also a 200 — a bare status-code check can't tell the two apart, content-type
has to be checked) → wrote and read back a real entry → uninstalled → `disabled_modules` immediately
included journal again, before any restart → confirmed the entry file was still on disk, byte-
identical. `npm run build` confirmed the actual production code-splitting: `Journal-*.js` and
`JournalEntryBlock-*.js` are genuinely separate chunks, not folded into the main bundle.

Real gap caught by this live check specifically (not by unit tests): journal was fully wired up but
had no `content/mod_store_catalog.json` entry — `get_catalog()` only ever iterates catalog entries,
so it would never have appeared in the Mod Store UI at all. Added it (`status: "available"`).

**Honest limitation**: no browser-automation tooling (Playwright/chromium-cli) is available in this
environment, so the actual React rendering was never visually verified — what's confirmed is the
real API cycle and the build output, not a screenshot-checked click-through. The Mod Store admin UI
itself (the page that would let an admin do this by clicking instead of curl) isn't built yet —
tracked in `docs/TASKS.md`.

**Safety note**: a broad `pkill -f "uvicorn main:app"` during manual testing nearly matched a real,
long-running instance on port 8000 under the same OS user — survived only because that specific PID
denied the kill signal. Switched to tracking and killing my own test instance by exact PID for the
rest of the session; the real instance was confirmed healthy throughout.

## Mod Store admin UI (increment 1, truly complete)

Built `pages/settings/admin/ModStore.jsx` — the piece that makes everything built today actually
usable by a human, not just curl. Wired into `AdminMenu.jsx` + `App.jsx` at
`/settings/admin/mod-store`. Seven explicit per-row states (`rowState()`) crossing the `installed`

whenever anything's pending in either direction; confirm-before-uninstall and the online-users

a custom modal.
