# 2026-09-08

## Full-repo audit (started 2026-09-06): security fixes, UX/redundancy batch, and 3 new reference docs

Continuation of the multi-day, multi-stage audit (documentation → security → UX consistency → redundancy → reference docs) that began 2026-09-06 under a dedicated `.claude/plans/whimsical-brewing-wolf.md` plan. Stage 1 (Documentation) and the first 4 items of Stage 2 (Security) were done in earlier sessions this week via a one-at-a-time interview. Today: the owner asked to fast-forward through the remaining ~50 findings across Security/UX/Redundancy/Reference-docs in one batch, with dispositions pre-assigned (fix/backlog/skip per item) and applied without further per-item confirmation.

**Method**: dispatched 9 parallel background subagents for the well-scoped, independent fixes (grouped by file-proximity to avoid merge conflicts), while personally handling the two highest-stakes items — the sharing-consolidation security fix and JSON-race-migration pieces — directly. Several agents hit a session-wide rate limit mid-task and were resumed via `SendMessage` once it cleared (same pattern as earlier in the week); all resumed cleanly. Every agent's diff was spot-checked before trusting its own summary, and the full backend suite was re-run repeatedly by different agents/sessions throughout — final count **1460 passed, 0 failed**.

### Security fixes shipped
- **X-Forwarded-For parsing** (`services/rate_limiter.py`) — was trusting the first (spoofable) entry instead of the last (proxy-appended) one; defeated every IP-keyed rate limit once `trust_proxy_headers` is on. Fixed + test corrected.
- **Stale admin JWT on `/register`** — the closed-registration admin-check hand-decoded the token and trusted its embedded `role` claim instead of re-fetching the user. A demoted/deleted admin's still-valid token could keep creating accounts. Fixed to re-fetch via `get_user_by_id`; new `tests/test_auth_register_admin_gate.py`.
- **`auth.json` role-update/delete had no lock**, unlike every sibling function in that file — a concurrent `PATCH /auth/me` could silently revert an admin's revoke/delete. Fixed with the existing `_auth_lock`; 2 new concurrency regression tests reproduce the lost-update without the fix.
- **The same unlocked-write race in Notes/Assets/Contacts/Finance's `update_access()`** — Finance's is concretely triggerable by the routine 12-hourly SimpleFIN sync job, no attacker timing needed. Fixed per-file (Finance/Notes/Assets got a small `(store_user, workspace)`-keyed lock covering `update_access()` + their one real concrete co-writer; Contacts routed through its existing `update_json()`-backed `_mutate_contact()` helper).
- **Privilege escalation in Assets'/Dashboard Templates' share-accept flow** — accepting your own group share notification could silently promote you to a completely different person's higher access grant on the same item, confirmed with a live PoC earlier in the audit. Extracted the already-correct check (from Finance/Contacts/Notes' own `respond_share()`) into a new shared `services/sharing.py`, wired into both buggy implementations. Deliberately not a full unification of all 5 services' sharing models — just the one shared bug-prone check. New regression tests in `test_assets_service.py`.
- **Home Assistant service-call passthrough** had no domain allowlist — a crafted `entity_id` could reach `homeassistant.restart`/`automation.turn_off`/`shell_command.*`. Now restricted to real device-control domains (light/switch/climate/lock/cover/fan/media_player/vacuum/scene).
- **n8n/Home Assistant admin-config endpoints** were missing their own module gate alongside `require_admin`, unlike Finance's established pairing pattern. Fixed on all 6 endpoints.
- **`POST /assets/{id}/convert`** was missing its module gate entirely. Fixed.
- **SSRF guard added to admin-configured AI provider `base_url`** (the "Load Models" live fetch) — reused the exact resolved-IP check `push_service.py` already had, extracted into new shared `services/net_safety.py`; local runners (Ollama, LM Studio, etc.) explicitly exempted since pointing at localhost is the whole point there.
- **AI tool resume/replay path now rechecks `disabled_modules`** at approval time — a write proposed while a module was enabled, then approved after the module was disabled, previously still executed; now skipped with a clear message.
- **`/docs`/`/redoc`/`/openapi.json`** now off by default (`ENABLE_API_DOCS` env var to opt back in) — were fully open, unauthenticated API-surface enumeration.
- **`GET /search`** had no rate limit, unlike every other endpoint. Fixed (30/min, matching the general-reads convention).
- **7 admin endpoints missing `_admin_limit`** (user create/role/delete, deletion-execute, hosting settings ×2, admin settings) — fixed. `CreateUserRequest.password` now enforces the same 8-char minimum as self-registration; `auth_service.create_user()` also rejects an empty password as a service-layer safety net.
- **HSTS logic** now gated behind `trust_proxy_headers` like the rate limiter already was, instead of trusting `X-Forwarded-Proto` unconditionally.
- **`launch.sh --reconfigure`** no longer silently regenerates `N8N_ENCRYPTION_KEY` when real n8n data exists — preserves the existing key when detected, or warns explicitly and pauses longer when it can't confirm one either way.
- **fastapi/starlette bumped** (0.111.0→0.115.14 / →0.46.2) closing a known multipart-DoS advisory (GHSA-2c2j-9gv5-cj73); verified no breaking API usage anywhere in the codebase first.
- **Notes' "Getting Started" note** now uses the atomic `write_markdown()` instead of a raw `write_text()` call.
- Removed genuinely dead code: `file_service.profile_path()`/`parse_priority_order()` (zero callers — `Profile.md` parsing hasn't been live since the Profile/Contacts merge) and the misleading `_template/Profile.md` file every new signup used to receive, which told users to edit a file nothing ever reads again. `docs/AGENTS.md`'s claim corrected — `profile.json` (JSON, not the markdown file) is still genuinely live, but only for the `_household`/`_team` pool pseudo-users.

**Deliberately not done this pass** (see TASKS.md): the broader JSON-race migration for every OTHER mutator in Assets/Finance/Dashboards (15-18+ call sites each) and the nightly `recurring_service` job's own unlocked write to `tasks.json`; upload content-type magic-byte validation; upload size limits enforced before full-body buffering; SimpleFIN redirect-chain re-validation; `home_assistant/backend/agent_tools.py`'s own service-call tool (found during the HA allowlist fix, same passthrough shape as the router endpoint that WAS fixed — flagged, not fixed, since it wasn't in original scope).

### UX fixes shipped
Household/Team got the same `EmptyState` treatment and pull-to-refresh every other list page already had. Login's Sign In/Create Account toggle and Automations' Workflows/Inbox switcher got the same ARIA-tablist arrow-key treatment already applied elsewhere. Fixed a real regression: clicking "Run" in Automations blanked the whole workflow list back to a loading spinner instead of refreshing in place (same non-blanking pattern Tasks/Contacts already use). Contacts/Assets/Finance delete confirmations now accurately describe what actually happens (Trash, 30-day recovery, and for Contacts specifically that interactions/deals are NOT recoverable even if the contact is restored) instead of a stale "cannot be undone" message. More icon-only buttons got real `aria-label`s (EmojiPicker's ~91 buttons, Tasks' done-toggle, others found in the same sweep), and several modal titles with unbounded dynamic text now truncate correctly on mobile instead of overflowing.
