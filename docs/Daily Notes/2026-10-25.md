## API keys, lead intake, and an MCP server

Owner asked to check the code first, then make LogCoreOS features reachable "with an api or mcp", maybe with API keys. Concrete ask: (1) fix the contacts automation upsert data-loss bug + phone/external_id dedup, (2) personal API keys with scopes, (3) a lead intake endpoint with a narrow `leads:create` scope, (4) an MCP server reusing the agent tool registry. Read the full docs set first (AGENTS/SOUL/MEMORY/TASKS/MAP/PROJECT/API/MODULE_AUTHORING/TESTING/DESIGN/COMPONENTS, the 2026-07-19 audit, README/SECURITY/CHANGELOG/RELEASING, docs/skills, docs/hooks; Daily Notes read selectively — the latest few in full, the rest grepped for MCP/API key/automation token) and wrote a plan before building.

**The plan surfaced one direct conflict for an owner ruling**: MEMORY 2026-07-12 says "per-employee API tokens would be a parallel auth system." Owner ruled **keys are admin-only** — so that decision still stands for employees; an admin's key is a credential for their own existing account (re-fetched every request, must still be admin, revoked with the account). Owner also chose `mcp:write` as an opt-in scope and an instance-wide "Allow API keys" switch defaulting on. Full rationale: `docs/MEMORY.md` Key Decisions Log, 2026-10-25, plus new Security Rule 22.

**What shipped** (branch `feat/api-keys-mcp`, one commit per step):
1. **Upsert fix** — the automation upsert sent every omitted field as `None` and partial validation treated each as "replace", so a sparse second call wiped emails/tags/notes and replaced phones (reproduced before fixing). New `contacts_service.upsert_external_contact()` merges (union emails/phones/tags, append notes, keep the existing name); `find_match()` gained `external_id` and phone matching, strongest signal first across the whole store; `external_id` is now stored. Found on the way: `_validate_phones` kept the FIRST 10 digits of "+1 501-555-0100" → "1501555010" — fixed. **Separate fix commit**: `_automation_store()` wrote `_team` contacts at the personal workspace, where no page reads them.
2. **API keys** — `services/api_key_service.py`, `routers/auth/api_keys.py`, Admin → API Keys page. `get_current_user` now rejects any `lcos_` token; only `require_api_key(scope)` routes accept one.
3. **Lead intake** — `POST /api/v1/contacts/intake/lead` (`leads:create`): upsert by phone/email/external_id (never by name alone — two people sharing a name must not merge), tag `website`, note interaction with a follow-up date in the owner's timezone. Response is ids only.
4. **MCP** — `POST /api/v1/mcp`, hand-rolled (the `mcp` SDK needs a newer pydantic than the 2.7.4 pin). Tools come straight from `agent_service._get_tools`/`_execute_tool`; read keys get read-only tools only; admin, chat-only, and metered tools never exposed; write calls audit-logged.
