**#32 (pull-to-refresh, the gesture itself)** — new `lib/usePullToRefresh.js`, hand-rolled touch-event
tracking (no gesture library added — small, well-understood amount of code, and this app's own
dependency philosophy favors that). `main.scrollTop === 0` (via `document.querySelector('main')`, the
same well-known-DOM-node shortcut Toast/ConfirmDialog already use for their own portals) gates when a
touch-down counts as "starting a pull"; elastic sqrt-damped resistance on the visual distance so it
doesn't track the finger 1:1. New `components/PullToRefreshIndicator.jsx` renders the small growing/
spinning ring.

Wired into Tasks, Contacts, Goals, Finance, Dashboard, and Brain — the same 6 pages (of the 7 the
diff-refresh fix touched) where it made sense. Two real complications found and designed around, not
guessed past:
- **Dashboard.jsx** disables the gesture (`enabled: !editing`) while its own block grid is in edit
  mode — react-grid-layout's own drag/resize handles live in the same scroll area, and Touch and
  Pointer events both fire for one physical gesture, so the two would otherwise compete for the same
  touch.
- **Notes.jsx deliberately excluded entirely** — its file-tree pane already has its own pointer-based
  drag-to-reorder (`onNotePointerDown`), the same conflict shape as Dashboard's but with no clean
  `enabled` toggle available (dragging is possible at any time, not gated by an edit-mode flag), and a
  drag starting at the very top of the tree would be genuinely ambiguous between "reorder" and "pull to
  refresh." Needs its own conflict-resolution design (e.g., suspending pull detection for the duration
  of any active `pointerdown` on a tree row) — flagged rather than rushed.
- **Brain.jsx** had no callable refresh function at all before this — its file list was only ever
  fetched inline inside a mount-only `useEffect`. Extracted into a real `loadFiles` (`useCallback`)
  first, mirroring every other page's own `load()` shape, so pull-to-refresh had something to call.
