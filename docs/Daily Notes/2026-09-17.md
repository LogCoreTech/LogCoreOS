Continuation of the 2026-09-06/08 full-repo audit (see that Daily Note for the original methodology and first batch). ### What shipped

- **Lock migration finished.** Every remaining unlocked `_save()` in `assets_service.py` (13 functions) and `finance_service.py` (11 functions) now holds the existing per-`(store_user, workspace)` lock. `dashboards_service.py` — funnels every mutator through one shared `_load`/`_save` pair rather than scattered call sites — got its own equivalent lock around each mutator's full body. The nightly `recurring_service.process_user()` write to `tasks.json` was restructured into a `file_service.update_json()` callback. New `_assets_locks_for(*keys)` helper (sorted+deduped `ExitStack`) added for the two functions that read-modify-write two different stores in one call (`transfer_ownership`, `convert_to_pool`) — avoids AB/BA deadlock between two concurrent transfers going opposite directions. Full detail + the durable pattern: `docs/MEMORY.md`'s 2026-09-16/17 Key Decisions Log entry.
- **`routers/auth.py` (1,251 lines, ~43 dependent files) split** into a `routers/auth/` package: `deps.py`/`session.py`/`profile.py`/`admin_users.py`/`admin_settings.py`/`__init__.py`. Verified via an exact 34-route diff against the original and a full import-site grep across the repo, not just "tests still pass."
- **Contacts' router (1,476 lines, 46 endpoints) and Assets' router (1,105 lines, 35 endpoints) split by concern**, following Finance's original 4-file precedent. Caught and fixed two real bugs during verification rather than after: Contacts' first `_get_router()` draft mutated a cached singleton router, which would have silently duplicated routes on a second call in the same process; Assets' core file's bare-path routes don't survive `include_router()`, solved by concatenating `.routes` lists onto a fresh `APIRouter()` instead.
- **Two large services partly extracted**, both via re-export rather than a full call-site migration (every caller uses `module.func()` attribute access, so re-export is equivalent-behavior for far less risk): `contacts_service.py` (2,110 → 1,896 lines) shed pipeline/interactions/deals into `contacts_deals_service.py`; `assets_service.py` (1,774 → 1,411 lines) shed templates/sharing/validation into `assets_templates_service.py`.
- **`home_assistant` got real test coverage** (35 tests) — the one module with no `tests/` directory before today. Also closed the mirror gap the security audit found in `agent_tools.py`'s `control_home_assistant_device` tool (an even more open domain passthrough than the router's own, now fixed the same day as that finding).
- **Finance transactions gained bulk-select** — the last of the 4 list-heavy modules to get it.
- **Button/label retrofit swept app-wide**: 29 files normalized to the canonical `block text-sm font-medium mb-1` label style; the destructive-button hover-direction convention was already fully compliant everywhere (no edits needed).

### A bug the verification pass found, not caused

Running the full suite after all 10 pieces landed left exactly one failure: `test_welcome_back_service.py::test_generate_summary_never_reads_another_users_journal`. Root cause: the test hardcoded a journal entry's date as `"2026-09-01"` while computing the "away since" cutoff as `datetime.now() - timedelta(days=8)` — the two only agreed while real "now" stayed in the first half of September, and broke on their own the moment today's date passed 2026-09-09, with no code change. Fixed by deriving the entry date the same relative way the cutoff is. Full writeup: `docs/MEMORY.md`'s Known Gotchas section (same bug class as the scheduler timezone gotchas already there).

### Verification discipline

Every one of the 10 agents' self-reports was independently checked before being counted done — file existence, route counts, re-export resolution, and (for the higher-risk ones) a from-scratch test run — following the same "trust but verify" rule the first batch established. Several agents also stalled mid-task believing a background job's completion would wake them automatically; subagents don't get that notification channel the way the main session does, so each had to be resumed with an explicit "check on it yourself." One agent's own mid-task `git stash` silently dropped 5 of 7 changed files on pop; caught by a line-count check, not by trusting the stash succeeded.
